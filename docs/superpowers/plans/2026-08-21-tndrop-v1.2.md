# TNDrop v1.2 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Tasks A→D 直列。

**Goal:** フィードバック第 2 弾 (v1.2.0): 画像スタックの分類/サムネ、スタック端ドラッグ 1 件抜き、ドラッグ中トリガー起動、設定画面の視認性+説明文、新アイコン。

## Global Constraints (v1/v1.1 から継承)

- 外部通信禁止 / NuGet 追加禁止 / UTF-8 no BOM LF / ログにパス・クリップボード内容禁止 / resx は ja+en+ラッパー同時 / XAML コメントに `--` 禁止 / 各タスクでテスト全緑 (現在 220) / コミットに Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>
- **実プロファイル (%APPDATA%\TNDrop) に触る検証は禁止** — プローブは必ず一時ディレクトリのストアを使う。
- **決定事項**: (1) 全ファイルが画像拡張子のスタック =「画像」フィルタ (混在・動画入りは「ファイル」)。(2) スタックカードのサムネ = 先頭ファイルが画像/動画なら大サムネ + 件数バッジ、それ以外は従来のシェルアイコン表示。(3) スタックカード自体をエッジ帯へドラッグ (DoDragDrop 戻り None ∧ カーソルがエッジ帯) → **先頭 1 件のみ** SplitFile で独立。(4) OLE ドラッグ中にトリガー帯に入ったらシェルフを開く (DragEnter — MouseEnter は OLE 中発火しないため)。

### Task A: 画像スタック分類 + スタックサムネイル

- ShelfViewModel: `IsSingleImageFile` を `IsImageEntity(item)` に拡張 — Kind==Image / 単独画像ファイル / **全パスが画像拡張子のスタック** を「画像」に分類。フィルタ・全 5 バッジ件数は引き続き 1 つの分類ヘルパー+1 つのシーケンスから導出 (v1.1 final の構造を維持)。
- CardViewModel: `StackThumbnail` 遅延プロパティ (IsStack ∧ MediaKind.Classify(Paths[0]) != Other → ShellImaging.GetThumbnail(Paths[0], 256))。
- Cards.xaml: スタックカードに StackThumbnail != null のときの大サムネ表示 (MediaFileContent と同じ寸法/角丸) + 右上件数バッジ維持 + ファイル名「ファイル N 件」1 行。null フォールバックは従来表示。
- テスト: 全画像スタック→CountImages に含まれ CountFiles から除外・Filter=Images に出る / 画像+txt 混在→Files / mp4 入り→Files / CountAll==サブ合計の不変条件維持。

### Task B: スタック端ドラッグ 1 件抜き + ドラッグ中トリガー起動

- ShelfWindow: スタックカードの DoDragDrop 完了後、効果 None ∧ StackGestures.IsInSplitZone(CursorDip) → Store.SplitFile(stackId, Paths[0]) + Save (フライアウト行の既存分割と同じ判定関数を再利用)。単独カード/非スタックは対象外。
- EdgeTriggerWindow: AllowDrop=true、DragEnter/DragOver で e.Effects=None のまま Triggered 相当のシェルフ表示要求を発火 (App 側の既存ゲート HoverEnabled/fullscreen を経由)。シェルフが開いたらトリガーは既存ロジックで隠れる → 開いたシェルフがそのままドロップ先になる。自アプリ発ドラッグは対象外にしない (シェルフ表示中はトリガー非表示のため実質外部ドラッグのみ)。
- テスト: 判定は既存の純粋関数を再利用するため新規ロジックのユニットは最小。プローブ: 一時ストアで DragEnter ハンドラ直接呼び→シェルフ表示、スタック端ドラッグの分割は DoDragDrop が実マウス必須のためチェックリスト行を追加 (未実施)。

### Task C: 設定画面の視認性 + 項目説明文

- SettingsWindow.xaml: 前景/背景を明示パレット化 (ラベル #E8E8EC、説明文 #9A9AA3、セクション見出し強調、コントロール前景明示)。システム既定色依存を排除。
- 各設定項目の直下に説明文 (既存の同種ツール準拠の文言を ja/en で作成、resx + ラッパー。例: ホバー表示「画面の端にカーソルを近づけるとシェルフをスライドで開く」、全画面保護相当は自動のため説明のみ等)。既存 3 カテゴリ全項目 (約 15) に付与。
- 説明文も TextScale 連動は不要 (固定 11px 相当・ただし明示色)。
- 検証: スクリーンショットで全項目の説明表示とコントラストを目視 + フォント色が明示指定であることを grep。

### Task E: 設定の新機能 4 項目 (ユーザー追加要望)

- AppSettings 追加: `PurgeUnpinnedOnRestart` (bool, 既定 false)、`HistoryCapacity` (int, 100/250/500/1000、既定 500)、`IndicatorEnabled` (bool, 既定 true)。既存 `EdgeHintEnabled` は維持 (意味を「トリガー近接ビーコン」に強化)。
- ItemStore: `TrimUnpinnedToCapacity(int max)` — 非ピンを新しい順に max 件残し、超過分を古い順に削除 (blob も DeleteBlobsFor 経由)。件数を返す。TryAdd 成功後の Save 前に CapturePipeline から呼ぶ (設定値は Func で注入)。
- App 起動時: PurgeUnpinnedOnRestart が true なら Load 直後に非ピン全削除 + Save (Info ログ件数のみ)。
- IndicatorEnabled=false → IndicatorWindow.Flash を呼ばない (App の一箇所でゲート)。
- エッジヒント強化: カーソルが設定エッジの近く (トリガー感度+余裕 ~8px) にあるがホットゾーン外のとき、EdgeTriggerWindow のヒントビーコンを点灯 (既存 SetHintVisible を近接判定で駆動 — 低頻度ポーリングは既存のカーソル取得経路を再利用)。EdgeHintEnabled で ON/OFF。
- 設定 UI 配置: [動作] 再起動時にピン留め以外を消去 / 履歴の容量 (4 択) を自動削除の下に。[位置] トリガー位置ヒント (EdgeHintEnabled を外観から移設・改名)。[外観] コピーインジケーター ON/OFF トグル (様式 4 択の上)。resx ja/en + ラッパー。
- テスト: TrimUnpinnedToCapacity (境界・ピン除外・blob 削除)、起動パージ相当のストア操作、設定既定値。

- テスト: VM 側は既存 SearchText のクリアのみで新ロジック無し (UI トリガーはプローブ)。プローブ: 長リストでスクロールバー描画確認 (スクリーンショット)、×の表示/クリアを検証。

### Task G: Windows スクリーンショットの取り込み (プライバシーフラグの値判定)

- 仮説: Snipping Tool は `CanIncludeInClipboardHistory` を付与し、現状の「存在だけで除外」実装がスクショを全スキップしている (既存の同種ツールも同様の実装で同症状)。
- ClipboardIo 修正: `ExcludeClipboardContentFromMonitorProcessing` と `Clipboard Viewer Ignore` は存在で除外 (現状維持)。`CanIncludeInClipboardHistory` は **DWORD 値を読み、0 のときだけ除外** (値 ≠0 または読めない場合は取り込む)。値読取は Win32 OpenClipboard/GetClipboardData(RegisterClipboardFormat) + 4 バイト読み (リトライ規律は既存準拠)。
- スキップ時の診断: プライバシー除外でスキップしたら Info ログに**フォーマット名のみ** (内容・サイズ不出力) を記録。
- テスト: DataObject に Bitmap+CanIncludeInClipboardHistory(値1/値0) を実際に SetClipboardData で構築し、値 1 → 取り込む / 値 0 → 除外 / Exclude 系存在 → 除外 を実クリップボードで検証 ([StaFact]、SuppressNext 等で自汚染防止、終了時クリップボード復元)。
- チェックリスト行: Win+Shift+S のスクショ → 画像カードが増える (未実施)。

### Task H: ピン留めアコーディオン + テキストのクリック貼り付け

- **ピン留めデッキ改修**: 横スクロール列を廃止し、既存の同種ツール同様の縦アコーディオンに。「📌 ピン留め N」ヘッダー行 (クリックで開閉、シェブロン回転、開閉状態は設定 `PinnedExpanded` に永続化)。展開時はピンカードを通常カードと同じ縦 1 列レイアウトでリスト上部に表示 (テンプレート・操作系は通常カードと共通)。VisibleCount 等の件数セマンティクスは不変。
- **クリック貼り付け (テキスト/リンク)**: シェルフは NOACTIVATE でフォアグラウンドを奪わないため、クリック時のフォアグラウンド = 貼り付け先。テキスト/Link カードの本体クリック時: SuppressNext + SetText → 物理修飾キー (Ctrl/Shift/Alt) が押されていないことを確認 → SendInput で Ctrl+V 送出 → MoveToTopOnCopy 等は従来どおり。検索ボックスにフォーカスがある場合と自アプリがフォアグラウンドの場合は貼り付けせず従来の再コピーのみ。設定 [動作] に「クリックで貼り付け」トグル (既定 ON、resx ja/en + 説明文)。ファイル/画像カードは従来どおり再コピーのみ (誤爆防止)。
- テスト: VM/純粋部 (開閉状態の永続化、対象カード種別判定)。SendInput 経路はプローブ (メモ帳を起動して実貼り付け確認 — 可能なら) + チェックリスト行。
