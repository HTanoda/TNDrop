# TNDrop v1.8.2 設計メモ: クリック貼り付けの誤抑止 (search-focus) の修正

日付: 2026-09-04 / 対象: v1.8.1 → v1.8.2 (bounded fix、計画書なし)

## 症状

「クリックで貼り付け」が全端末 (本番機 2 台以上・開発機) で効かない。カードクリックの再コピー
(音・フラッシュ) は起きるが Ctrl+V が送られない。ログは毎回
`[INFO] ShelfWindow: paste suppressed: search-focus`。検索ボックスは使っていない。

## 根本原因

1. シェルフは `WS_EX_NOACTIVATE`。クリックしても**前面ウィンドウ**にはならないが、Windows は
   WM_MOUSEACTIVATE で**そのウィンドウを自スレッドのアクティブウィンドウにし、スレッドの
   キーボードフォーカスも与える** (GetGUIThreadInfo で `active=シェルフ, focus=シェルフ,
   前面=別アプリ` を実測)。
2. WPF は WM_SETFOCUS を受けてクリックされた ListBoxItem (Card.ListBoxItemStyle は Focusable
   既定 true) にキーボードフォーカスを置く。`IsKeyboardFocusWithin` が真になる。
3. シェルフのスレッドは前面スレッドになったことがないので、利用者が他アプリに戻っても
   WM_KILLFOCUS が届かず、旗はシェルフが Hide されるまで立ちっぱなし。
4. `ClickPaste.Resolve` はこの旗を「検索ボックスにフォーカスあり」と解釈して抑止。
   さらに `IsPointerInside` も同じ旗を読むため、格納カウントダウンが起動せずシェルフが
   開いたままになり、旗が消える機会 (Hide) も失われる。

WPF 側の根拠: `HwndKeyboardInputProvider.AcquireFocus` は NOACTIVATE ウィンドウでは
SetFocus を呼ばず「スレッドが何かにフォーカスを持っていれば成功」を返す。
実 SendInput クリックの再現ハーネス (scratchpad FocusRepro) で、起動直後の初回クリックの
マウスダウン時点で `IsKeyboardFocusWithin=True`、Hide で False、以後の再クリックでは
再発しない (スレッドのアクティブが既にシェルフのため) ことを確認。再発条件は、起動直後と、
別の TNDrop ウィンドウ (設定 / 編集 / 名前変更 / バックアップ / トレイメニュー / 検索
ボックス) を使った後の最初のシェルフクリック。

v1.3 で「理由コードが出ている = ガードの正常動作」と誤判定していた
(failures/20260904-guard-reason-code-taken-as-proof-of-correct-behavior.md)。

## 修正 (3 層)

1. **発生させない**: `ShelfWindow.OnSourceInitialized` で HwndSource フックを追加し
   WM_MOUSEACTIVATE に `MA_NOACTIVATE` を返す。スレッドローカルの活性化・フォーカス取得も
   辞退する。検索ボックスの例外経路は明示 `SetForegroundWindow` なので影響なし。
   `StackFlyout.OnOpened` でも Popup の HWND に同じフックを付ける (Popup は開くたびに
   HWND を作り直すため毎回付け直す)。
2. **WPF 側でも取らせない**: `Card.ListBoxItemStyle` / `Card.ActionButton` (Pin・Edit・
   Rename・Delete が継承) / `FilterTabButtonStyle` / `SelectionBarButtonStyle` /
   `Flyout.HeaderButtonStyle` に `Focusable=False`。`CardsList` と `ClearButton` にも直接
   指定。ダイアログを開いたまま (スレッドがフォーカスを持つ状態で) シェルフを触った場合も
   フォーカスが移らない。
3. **残っていても自己修復**: 新設 `ShelfFocus.IsLive / IsStale` (純粋関数・テスト済み) で
   「フォーカス within かつ自プロセスが前面」だけを本物のフォーカスと解釈する。
   `TryPasteOnClick` は前面判定を 1 回だけ読み、Stale なら `Keyboard.ClearFocus()` して
   Info ログ (`cleared stale keyboard focus ...`) を残し貼り付けを続行。
   `IsPointerInside` の項も `HasLiveKeyboardFocus` に置き換え、格納が詰まらないようにする。
   `ClickPaste.Resolve` 自体 (5 引数の契約とテスト) は変更しない。

## 検証

- 単体: ShelfFocusTests (12 件) 追加、既存含め 558 件 green。
- 実機 (開発機): 起動直後にメモ帳へカーソルを置き、カードをクリック → 貼り付けが起き、
  ログに `paste suppressed` が出ない。GetGUIThreadInfo で TNDrop スレッドの focus が 0 の
  まま。クリック後にカーソルを離すと従来どおり格納される。手順は
  docs/manual-test-checklist.md §36。

## 副観測 (未対応)

本番機ログではカードクリックのたびに `placed on ...` (DpiChanged → ApplySettings) が出る。
混在 DPI 環境での再配置で、今回の原因ではない。別件として扱う。
