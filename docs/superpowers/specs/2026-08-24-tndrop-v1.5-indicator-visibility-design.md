# TNDrop v1.5 設計書: インジケーター視認性の改善と自動開始デフォルト有効化

日付: 2026-08-24
状態: ユーザー承認済み (ブレインストーミングで各論点を確認)

## 背景

v1.4.2 の本番リリース後、エンドユーザーと開発者自身から次のフィードバックを得た:

- デスクトップ背景やウインドウが明るい環境では、キャプチャ確認のインジケーターが
  ほぼ見えない。現在の全 4 スタイル (ビーコン/バー/パルス/コーナー) は
  「細い・半透明・短時間」で、色は水色 #5AC8FA を白方向に +35% 明るくしたもの
  (v1.3 Task E の IndicatorBrightness)。暗い背景向けの明るさブーストが、
  明るい背景ではちょうど逆効果になっている。
- インジケーターの色や透明度を設定で変えられるようにしてほしい。
- 「起動時に自動で開始する」はデフォルト有効のほうがよい。

## 決定事項 (ブレインストーミングでの合意)

| 論点 | 決定 |
| --- | --- |
| デフォルト視認性の改善方針 | 縁取り方式 (明るい塗り + 暗い縁のコントラストペア) |
| 色の選び方 | プリセットパレット 8 色 (自由入力・カラーピッカーなし) |
| 透明度 | スライダー 30〜100% |
| 自動開始の既存ユーザー扱い | 一回限りの移行で ON にする (以降のユーザー操作を尊重) |
| 参考画像の「うにょっと出るふくらみ」 | 第 5 のスタイル Bulge として追加し、新規インストールの新デフォルトにする |
| 既存ユーザーのスタイル | 移行しない (意図的な選択と区別がつかないため)。縁取り改善で視認性は解決する |

## パート 1: 色解決の一元化 (IndicatorPalette) と既存 4 スタイルの縁取り

### IndicatorPalette

`IndicatorBrightness` (白方向ブースト) を廃止し、新しい純粋関数クラス
`IndicatorPalette` に置き換える。基準色 1 つから関連する全色を **1 回の解決で**
導出する (one-resolution-per-related-fields ルール準拠):

```
IndicatorPalette.Resolve(Color base) → (Fill, Outline, Rim)
```

- **Fill (塗り)**: 基準色そのまま、不透明 (alpha 255)。
- **Outline (縁取り / Bulge 本体)**: 基準色を黒方向へ固定率 (65%) ブレンドした不透明色。
- **Rim (Bulge の外周リム)**: 基準色を白方向へ固定率 (60%) ブレンドした不透明色。

固定率は実装時に実機で微調整してよいが、**3 色とも必ずこの 1 関数から導出する**。
呼び出し側 (IndicatorWindow / Bulge) は戻り値のみを使い、独自に色を計算しない。
`IndicatorBrightness` とそのテスト (IndicatorBrightnessTests) は削除する。

### 既存 4 スタイルの縁取り

各スタイルの視覚要素を「本体 + 縁」のコンテナ (Grid) にまとめ、
フラッシュのアニメーションは**コンテナの Opacity** に対して行う
(本体と縁が常に同時に光る。既存の restart 動作・FillBehavior は維持):

- **ビーコン**: 6px の光の背後に 10px 幅の縁取り矩形。縁側も同じ縦グラデーション
  (透明 → Outline → 透明) で、端のフェードを揃える。
- **バー**: 3px バーの背後に 7px 幅の Outline 矩形 (全高)。
- **パルス**: Ellipse に Stroke=Outline (2px) を付ける。ScaleTransform で縁も一緒に
  拡大されるのは許容 (拡大中も輪郭が残るほうが視認に有利)。
- **コーナー**: Ellipse に Stroke=Outline (1.5px)。

明るい背景では暗い縁が、暗い背景では明るい塗りが効く。

## パート 2: 設定 (色プリセット + 透明度スライダー)

### AppSettings 追加

```csharp
public string IndicatorColor { get; set; } = "#5AC8FA";   // HEX #RRGGBB
public int IndicatorOpacityPercent { get; set; } = 100;   // 30〜100
public const int MinIndicatorOpacityPercent = 30;
public const int MaxIndicatorOpacityPercent = 100;
```

- SettingsStore.Load で HistoryCapacity と同じ方針のサニタイズを行う:
  - `IndicatorOpacityPercent` は [30, 100] にクランプ (30 未満は「設定したのに
    全く見えない」事故防止)。
  - `IndicatorColor` がパース不能な文字列ならデフォルト "#5AC8FA" にフォールバック。
    パースは `#RRGGBB` 形式のみ受理 (alpha は透明度設定と二重になるため受けない)。

### 透明度の適用

フラッシュのピーク不透明度に乗算する。既存の `Opacity = 1.0` から開始する箇所を
`Opacity = IndicatorOpacityPercent / 100.0` から開始に変更し、フェードの From も
同値にする。Bulge にも同様に適用 (ウインドウではなく該当ビジュアルの Opacity)。

### 設定 UI (外観タブ)

「インジケーターのスタイル」フィールドグループの下に追加:

- **色**: 8 色の丸スワッチのラジオ列 (RadioButton の再テンプレートで円形色見本 +
  選択リング。既存の再テンプレート方針に従い、色はすべて明示指定)。
  プリセット: 水色 #5AC8FA (デフォルト) / 青 #0A84FF / 緑 #34C759 /
  オレンジ #FF9F0A / レッド #FF453A / パープル #BF5AF2 / 白 #FFFFFF /
  グレー #8E8E93。保存値は HEX 文字列そのもの (プリセット外の値が settings.json に
  手書きされていても、パースできれば尊重して選択なし表示)。
- **透明度**: 既存 Slider スタイルを流用、30〜100%、現在値表示付き。

どちらの変更も既存の App.Set* パターンに従う (`SetIndicatorColor` /
`SetIndicatorOpacityPercent` を App に追加し、Settings 書き込み + SaveSettings +
IndicatorWindow への反映)。変更直後に既存のスタイル切替と同じ
プレビューフラッシュを鳴らす (App.FlashIndicator のプレビュー経路)。

Strings.resx / Strings.en.resx に追加する文言: 色ラベル (「色」/ "Color")、
透明度ラベル (「透明度」/ "Opacity")、透明度の現在値・説明文、各色名
(ツールチップ用)、Bulge スタイル名 (「ふくらみ」/ "Bulge")。

## パート 3: 自動開始のデフォルト有効化 (一回限り移行)

- `AppSettings.AutoStartEnabled` のデフォルトを `true` に変更。
- 移行フラグを追加: `public bool AutoStartDefaultMigrated { get; set; } = false;`
- App.OnStartup の設定ロード直後 (既存のレジストリ自己修復より**前**) に:

```
if (!Settings.AutoStartDefaultMigrated)
{
    Settings.AutoStartEnabled = true;
    Settings.AutoStartDefaultMigrated = true;
    SaveSettings();
}
```

- 直後に走る既存の自己修復 (`ExpectedCommand` と `GetStoredCommand` の比較) が
  同じ起動内でレジストリ Run 値を書き、自動開始が実際に有効になる。
- 新規インストール (settings.json なし) もこの経路で ON + フラグ保存。
- 移行後にユーザーが OFF にすれば、フラグが立っているので以降は尊重される。
- v1.4 以前で意図的に OFF にしていたユーザーも一度だけ ON に戻る。これは
  「現状 OFF のユーザーはほぼ全員デフォルトのまま触っていない」という推定に基づく
  合意済みのトレードオフ。

## パート 4: 「ふくらみ」(Bulge) スタイル — 新規・新デフォルト

### 見た目

- `IndicatorStyle` に `Bulge` を追加 (5 番目)。`AppSettings.IndicatorStyle` の
  デフォルトを `IndicatorStyle.Bulge` に変更 (新規インストールのみ影響。
  既存ユーザーのスタイルは移行しない)。
- 画面端から膨らむ滑らかなベジェのこぶ: 高さ約 140px、突出約 28px、
  ワークエリア縦中央、設定されたエッジ側。PathGeometry で描く
  (端に接する辺は直線、外周は滑らかな 3 次ベジェの膨らみ)。
- 本体 Fill = Palette.Outline (濃色・不透明)。外周に沿って Palette.Rim の
  細いリム (1.5px) — 暗い背景対策 (縁取り原理の反転)。
- 中央に白い簡略クリップボードグリフ (自作の XAML Path、幅 14px 程度)。
  不透明ボディ + 白グリフの「図と地」ペアで背景色に依存しない。

### 動き (apple-design 指針の適用)

- **出現**: ScaleTransform X を 0→1 (RenderTransformOrigin をエッジ側に固定)。
  約 350ms、軽いオーバーシュート (BackEase EaseOut, Amplitude≈0.3 相当)。
  オーバーシュートは「うにょっ」という物性の性格づけとして意図的に採用
  (既定は critically damped という指針の、根拠を持った例外)。
- **保持**: 約 400ms。
- **退場**: 同じ経路を X 1→0 で戻る (spatial consistency: 出た方向へ戻る)。
  約 300ms、QuadraticEase EaseIn、バウンスなし。
- 合計約 1.05s。連続キャプチャ時は既存スタイルと同じく restart
  (アニメーション途中でも先頭からやり直し。既存の Flash 呼び出し規約を維持)。
- 実装は既存 IndicatorWindow に BulgePath 要素と FlashBulge メソッドを追加する形。
  クリック透過・非アクティブ・Topmost は既存ウインドウの性質をそのまま使う。

### 設定 UI への追加

外観タブのスタイルラジオ列に「ふくらみ」を追加 (5 個目)。選択時のプレビュー
フラッシュは既存経路で動く。

## データ互換性

- settings.json への追加キー: `IndicatorColor` / `IndicatorOpacityPercent` /
  `AutoStartDefaultMigrated`。旧バージョンのファイルにはキーが無いだけなので、
  デシリアライズはデフォルト値で埋まる (既存の後方互換ロードと同じ)。
- `IndicatorStyle` の JSON 表現に `Bulge` が増える。旧バージョンへのダウングレードは
  サポート対象外 (従来からの方針どおり)。

## テスト

- **IndicatorPaletteTests** (新規): Fill/Outline/Rim が 1 回の Resolve から導出される
  こと、Outline は Fill より暗い・Rim は Fill より明るい (BT.601 輝度で比較)、
  黒・白などの端の色でも破綻しない (クランプ)。
- **SettingsStoreTests** (追加): 透明度の範囲外クランプ (29→30, 101→100)、
  不正 HEX ("xyz", "#12", 空) のフォールバック、正常 HEX の保持。
  AutoStartEnabled / AutoStartDefaultMigrated / IndicatorStyle の新デフォルト値。
- **移行ロジックのテスト**: フラグ false → AutoStartEnabled が true になりフラグが
  立つ / フラグ true → AutoStartEnabled は現状維持 (false のままなら false)。
  移行判定を純粋関数に切り出してテストする (App.OnStartup 内のベタ書きにしない)。
- **IndicatorBrightnessTests は削除** (クラスごと廃止のため)。
- 手動テストチェックリスト (docs/manual-test-checklist.md) に追加:
  - 白いウインドウを最大化した状態で 5 スタイルすべてのフラッシュが視認できること。
  - 色スワッチ・透明度スライダーの変更が即座にプレビューされ、再起動後も保持される
    こと。
  - v1.4.x からの上書きインストール後の初回起動で自動開始が ON になり、
    サインイン後に TNDrop が起動すること。OFF に戻した後の再起動で OFF が保持される
    こと。
  - ふくらみの出現・退場アニメーションがマルチモニター/DPI 混在環境で正しい位置に
    出ること。

## 非スコープ (今回やらないこと)

- 既存ユーザーの IndicatorStyle 移行 (上記のとおり意図的に行わない)。
- 自由入力のカラーピッカー / HEX テキスト入力。
- OS の「アニメーションを無効にする」設定への追従 (既存スタイルも未対応。
  将来課題として認識のみ)。
- インジケーターのサイズ・表示時間の設定化。
