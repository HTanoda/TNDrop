# TNDrop v1.7 設計書 — テキスト編集機能

日付: 2026-08-29 / 対象バージョン: 1.7.0 / ステータス: ユーザー承認済み設計

## 1. 目的とスコープ

利用者要望「テキストの編集機能 (ピン止めと削除のアイコンの間に編集アイコンを追加)」に応える。

含むもの:

- テキストカード・リンクカードへの編集アイコン追加 (カードのアクション列、ピンと削除の間)
- 専用の編集ダイアログ (複数行テキストボックス + 保存/キャンセル)
- 保存時の本文・種別・重複判定ハッシュの同時更新 (種別は `UrlDetector.IsUrl` で再判定)

含まないもの (明示的に見送り):

- 画像・ファイル・スタックカードの編集 (編集アイコン自体を出さない)
- カード内インライン編集 (シェルフの no-activate 設計と衝突し実装が重い — ダイアログ方式を採用)
- 保存時のクリップボードへのコピーや先頭への移動 (「保存のみ」。コピーは従来どおりカードクリック)
- 編集履歴 / 元に戻す機能

## 2. 保存時の意味論 (最重要)

編集の保存は **1 回の解決で 3 つの関連項目を同時に更新する**:

| 項目 | 更新内容 |
|---|---|
| `ClipItem.Text` | 編集後の本文 |
| `ClipItem.Kind` | `UrlDetector.IsUrl(newText) ? ClipKind.Link : ClipKind.Text` — コピー時の判定 (ClipboardIo / DragDropTarget) と同じ関数で再判定 |
| `ClipItem.ContentHash` | `ItemStore.Fnv1a(UTF8(newText))` — CapturePipeline のテキストハッシュと同じ導出 |

- 例: 先頭の h が欠けた `ttps://…` のテキストカードに h を足して保存 → リンクカードになり、「ブラウザで開く」ホットスポットとリンクフィルタタブが追従する。逆に URL を文章に書き換えればテキストカードに戻る
- 変えないもの: `Id` / `CreatedAtUtc` / `Pinned` (カードの位置・日時・ピン状態は維持)
- この 3 項目更新は `ItemStore` の新メソッドを唯一の入口とし、UI 側で個別に触らない
  (関連項目を別々の規則で決めない — rules/one-resolution-per-related-fields.md の適用)

## 3. ItemStore API

```csharp
/// <summary>編集ダイアログの保存。Text/Kind/ContentHash を 1 回で同時更新して Save() する。</summary>
/// <returns>対象 id が存在し更新した場合 true。見つからない場合 false (何もしない)。</returns>
public bool UpdateText(string id, string newText)
```

- ロック下で対象を検索。`newText` が null / 空 / 空白のみなら `ArgumentException` (ダイアログ側で保存ボタンを無効化するため通常到達しないが、二重防御)
- 永続化と `Changed` 発火のタイミングは、既存の変異メソッド (`SetPinned` 等) の実物を実装時に確認して同じ形にする (Changed はロックの外で発火する — これは既存全メソッド共通の確定作法)
- 対象外の種別 (Image/Files) の id を渡された場合も false (UI がアイコンを出さないため通常到達しない)

## 4. 編集ダイアログ (EditDialog)

- WPF、BackupDialog / PasswordDialog と同じ作法: 標準ウインドウクロム、CenterScreen、ShowInTaskbar=False、ダークパレット、全フォーカス可能コントロールに FocusVisual、XAML コメントに `--` を書かない
- 構成: 複数行 TextBox (`AcceptsReturn=True`、縦スクロール、幅 480 高さ 320 程度、等幅でない通常フォント) + 「保存(_S)」「キャンセル」ボタン
- 保存ボタンは本文が空白のみのとき無効
- **単一インスタンス**: App が `OnOpenSettingsRequested` と同型で管理。既に開いているときに別カードの編集を押しても**前面化のみ** (未保存の編集内容を黙って捨てない)
- シェルフとの関係: 独立ウインドウなので、開いた後にシェルフが自動格納されても編集は継続できる。保存すると `Changed` 経由でカード表示・フィルタ件数が更新される
- 編集中に対象カードが消えた場合 (削除・自動削除・リストア): 保存時に `UpdateText` が false →
  「このカードは既に削除されています。」を表示してダイアログを閉じる

## 5. カード UI (Cards.xaml + ShelfWindow)

- アクション列に `Tag="Edit"` のボタンを **ピンと削除の間** に追加。既存の Pin/Delete と同じ `Card.ActionButton` スタイル + class handler 方式 (ShelfWindow に Tag 分岐を 1 つ追加)
- 表示条件: `Kind` が Text または Link のカードのみ Visible (それ以外は Collapsed)。既存の DataTrigger 流儀に合わせる
- ツールチップ / AutomationProperties.Name に新文言 `ActionEdit`

## 7. テスト

単体テスト (xunit、既存流儀):

- `UpdateText`: テキスト→リンク / リンク→テキストの双方向で Text/Kind/ContentHash の 3 項目が同時に正しく更新される (ContentHash は `Fnv1a(UTF8(newText))` と一致することを直接検証)
- 永続化往復: UpdateText 後に別インスタンスで Load して反映されている
- 不在 id → false・無変更。空白のみ → ArgumentException
- Id / CreatedAtUtc / Pinned が変わらないこと
- Changed が発火すること

実機チェックリスト (§32 として追加):

- 編集アイコンがテキスト/リンクカードだけに出る (画像・ファイル・スタックには出ない)
- 編集 → 保存でカード表示が即時更新される (再起動不要)
- `ttps://…` に h を足す → リンクカード化し「開く」が効く、リンクタブに移る。逆方向も
- 編集中にシェルフが格納されても保存できる
- 編集中にカードを削除 → 保存時に「既に削除されています」
- 編集ダイアログを開いたまま別カードの編集を押す → 前面化のみ
