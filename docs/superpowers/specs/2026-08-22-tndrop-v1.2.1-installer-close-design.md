# TNDrop v1.2.1 設計: インストーラーの実行中アプリ自動クローズ

日付: 2026-08-22 / 対象: v1.2.1 (パッチリリース)

## 問題

セットアップ起動時に実行中の TNDrop を検出すると、Inno Setup 標準の「閉じてください」
ダイアログ (`AppMutex` 由来) が出て先へ進めない。TNDrop はタスクバーに現れないトレイ常駐
アプリのため、エンドユーザーは閉じ方が分からず、インストール/アップデートが行き止まりになる。

## 解決策

インストーラーが検出時に「終了して続行するか」を尋ね、承諾されたら自分でアプリを閉じる。
閉じ方は正常終了優先 + 強制終了フォールバックの 2 段構え。

### 1. アプリ側: 終了要求イベントの待ち受け (v1.2.1)

- 名前付きイベント **`Local\TNDrop_ShutdownRequest`** (AutoReset) を単一インスタンス Mutex と
  同時に作成し、待ち受ける。合図を受けたら Dispatcher 経由で `Shutdown()` を呼ぶ
  (トレイ「終了」の `OnExitRequested` と同じ経路。保存・トレイアイコン破棄・Mutex 解放は
  既存の `OnExit` がそのまま行う)。
- 待ち受けは小さなクラス `ShutdownSignal` (Platform/) に切り出す:
  - `ShutdownSignal(string eventName, Action onSignaled)` — `EventWaitHandle` 作成 +
    `ThreadPool.RegisterWaitForSingleObject` (executeOnlyOnce: false は不要、一度で足りるが
    再武装してもよい)。コールバックはワーカースレッドで届く前提とし、Dispatcher への
    マーシャリングは呼び出し側 (App) が行う。
  - `IDisposable` — 登録解除 + ハンドル破棄。App.OnExit で破棄。
  - イベント名は引数で受け、テストは一時名で駆動する (実名の定数は App 側)。
- 単一インスタンスの敗者側 (二重起動) はイベントを作成しない (Mutex 判定で早期 Shutdown
  する既存分岐より後に初期化する)。

### 2. インストーラー側: setup.iss [Code]

- `InitializeSetup` と `InitializeUninstall` の両方で:
  1. `CheckForMutexes('Local\TNDrop_SingleInstance')` で実行中を判定。非実行なら素通り。
  2. 実行中なら MsgBox (はい/いいえ):
     ja「TNDrop が実行中です。終了してインストールを続行しますか?」
     (アンインストール時は文言を差し替え)。en も用意し `[CustomMessages]` で ja/en 両対応。
  3. いいえ → False を返して中止。
  4. はい → `TryCloseRunningApp()`:
     a. kernel32 の `OpenEvent`/`SetEvent`/`CloseHandle` を external 宣言し、
        `Local\TNDrop_ShutdownRequest` に合図 (旧版はイベントが無く OpenEvent が 0 を返す
        だけ — そのまま b の待ちへ)。Mutex 消失を最大 5 秒ポーリング (250–500ms 間隔)。
     b. まだ実行中なら `taskkill.exe /F /IM TNDrop.exe` (SW_HIDE, ewWaitUntilTerminated) に
        フォールバックし、さらに最大 5 秒ポーリング。
     c. それでも実行中なら「TNDrop を終了できませんでした。手動で終了してから再実行して
        ください」を表示して False (中止)。
- 既存の `AppMutex=Local\TNDrop_SingleInstance` 行は**安全網として残す** ([Code] をすり抜けた
  場合でも標準ダイアログで止まり、閉じずに上書きされる事故は起きない)。
- AppId GUID・32-bit インストーラー方針・PrivilegesRequired=lowest は不変 (確定方針)。

### 3. リリース

- csproj / setup.iss とも **1.2.1** (version-consistency テストが両方を強制)。
- `build.ps1` で `dist\TNDrop-Setup-1.2.1.exe` を生成。
- checklist に **§23 (v1.2.1)** を追加 (すべて 未実施):
  実行中に setup → 確認 → はい → 終了して続行 / いいえ → 中止 /
  アップデート完了後に「起動する」で再開 / アンインストール時も同様 /
  旧版 (イベント非対応) からのアップデートでもフォールバックで閉じる。

## 動作マトリクス

| 状況 | 経路 |
|---|---|
| v1.2.1 以降が実行中 | イベント合図 → 正常終了 (保存・後始末が走る) |
| v1.1〜v1.2.0 が実行中 (今回の症状) | イベント空振り → 5 秒後に taskkill /F |
| 非実行 | 確認なしでそのまま続行 |
| 終了失敗 | メッセージを出して中止 (AppMutex 安全網も残存) |

## テスト

- `ShutdownSignal`: 一時イベント名で作成 → 別ハンドルから Set → コールバック発火を待って
  assert / Dispose 後は発火しない。実クリップボード・実プロファイルに触れない。
- バージョン整合: 既存 `AppVersionTests` が 1.2.1 の両ファイル更新を強制。
- インストーラー [Code] は自動テスト不能 → checklist §23 (実機)。

## 制約 (v1.2 から継承)

外部通信禁止 / NuGet 追加禁止 / UTF-8 no BOM LF (.iss は UTF-8 BOM CRLF) /
ログにパス・クリップボード内容禁止 / XAML コメント `--` 禁止 / resx 変更時は ja+en+ラッパー /
実プロファイル (%APPDATA%\TNDrop) に触る検証禁止 / インストーラーは実行しない (ビルドまで)。
