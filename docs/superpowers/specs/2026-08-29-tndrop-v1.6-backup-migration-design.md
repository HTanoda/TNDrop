# TNDrop v1.6 設計書 — データのバックアップ・リストアと別端末移行

日付: 2026-08-29 / 対象バージョン: 1.6.0 / ステータス: ユーザー承認済み設計

## 1. 目的とスコープ

利用者要望「データ (履歴、ピン止め履歴、設定) のバックアップ&リストア」「別端末への移行」に応える。

含むもの:

- 手動バックアップ / 自動バックアップ (日次 + 終了時) / リストア / バックアップ削除
- 別端末移行用のエクスポート & インポート (パスワード必須の暗号化ファイル)
- 管理ダイアログ「データのバックアップ・移行」(トレイメニューと設定画面から開く)
- 同梱の小変更: 設定画面「格納までの時間」スライダーの下限を 300ms → 100ms に変更
  (エンジン側 `ShelfWindow.ApplySettings` の clamp 下限 100ms と一致させる。clamp 自体は変更しない)

含まないもの (明示的に見送り):

- テキスト編集機能 (カードの編集アイコン) — v1.7 候補
- バックアップのマージ復元 — 全置き換えのみ (§5)
- 世代数・バックアップ先フォルダの設定項目化 — 固定値で出し、要望が出たら設定化
- 定期 (毎時等) バックアップ — 日次 + 終了時で足りると判断

## 2. 用語とデータの範囲

「データ一式」= `%APPDATA%\TNDrop\` 配下の次の 3 点。ログは含めない。

| 対象 | 内容 | 暗号化 |
|---|---|---|
| `items.dat` | 履歴 + ピン止め (JSON) | DPAPI (CurrentUser) |
| `blobs\` | 画像 PNG | なし |
| `settings.json` | 設定 | なし |

DPAPI (CurrentUser) は同一 PC・同一 Windows ユーザーでのみ復号できる。この性質が
バックアップ (同一環境での復旧、暗号化のままコピー) とエクスポート (別環境への移行、
復号してパスワード暗号化に詰め替え) を分ける理由である。

## 3. バックアップの形式・保存先・世代管理

- 形式: データ一式を **復号せず** そのまま ZIP に格納 (平文はディスクに残らない)。
  ZIP 内ルートに `manifest.json` を同梱する:
  `{ "format": 1, "appVersion": "1.6.0", "createdUtc": "...", "kind": "auto|manual|safety|export" }`
- 保存先: `%APPDATA%\TNDrop\backups\` 固定。
- ファイル名と世代管理:

| 種別 | ファイル名 | 作成契機 | 世代管理 |
|---|---|---|---|
| 自動 | `auto-YYYYMMDD.zip` | §4 (日次 + 終了時) | 1 日 1 ファイル (同日は上書き)。新しい順 7 件を保持、超過分を削除 |
| 手動 | `manual-YYYYMMDD-HHmmss.zip` | ダイアログの「手動バックアップ」 | 自動削除しない。ダイアログの「削除」で利用者が管理 |
| 退避 | `safety-YYYYMMDD-HHmmss.zip` | リストア / インポートの直前 (§5) | 新しい順 3 件を保持、超過分を削除 |

- 一覧の表示名は `[自動] / [手動] / [退避] + 作成日時` (日時は manifest の createdUtc をローカル時刻で表示)。
- 整合性: バックアップ作成は ItemStore のロック下でデータ一式をスナップショットしてから
  ZIP 化する (`Save()` の tmp/dat/bak 差し替えや blobs 追記と交錯させない)。
- 刈り込み判定 (どのファイルを消すか) は純関数 `BackupPruning` に切り出して単体テストする。

## 4. 自動バックアップの契機

- 日次: その日最初の履歴保存 (`ItemStore.Save()` 成功後) に 1 回。最終自動バックアップ日
  (`yyyy-MM-dd`) を settings.json に記録して同日 2 回目以降を抑止する。
- 終了時: ① WPF `Application.SessionEnding` (シャットダウン / サインアウト)、
  ② トレイメニュー「TNDrop を終了」。同日の `auto-YYYYMMDD.zip` を上書きして最新化する。
  SessionEnding には OS の応答時間制約があるため、この経路では失敗時のリトライをしない
  (書けなければログして諦める。翌日の日次が拾う)。
- 設定 `AutoBackupEnabled` (bool、既定 true) を追加。設定画面にトグルを置く。OFF は
  自動 (日次 + 終了時) のみ止める。手動 / 退避には影響しない。
- 自動バックアップの失敗は通常動作を止めない (WARN ログのみ、ダイアログ表示なし)。

## 5. リストアとインポートの共通復元フロー (全置き換え)

リストアもインポートも「現在のデータ一式を丸ごと置き換えるスナップショット復元」で、
次の共通フローを通る:

1. 確認ダイアログ (「現在の履歴・ピン・設定は選択したバックアップの内容で置き換えられます。
   実行前に現在の状態を自動退避します。」)
2. 現在の状態を `safety-*.zip` として退避 (§3)。退避に失敗したら中断する。
3. 取り込み元を検証: manifest の存在と format、必須エントリ (items.dat / settings.json) の存在。
   リストアの場合はさらに items.dat が DPAPI で復号できることを確認する。復号できなければ
   「このバックアップは別の PC または別のユーザーで作成されたため復元できません。
   別の PC への移行にはエクスポート機能を使ってください。」と案内して中断する。
4. クリップボード監視と自動保存を一時停止し、ItemStore のロック下でファイルを差し替える。
5. アプリ内で再読込する (再起動しない): `ItemStore.Load()` → 設定の再読込と全面再適用
   (シェルフ / インジケーター / ホットキー / 自動開始など、起動時と同じ適用経路を通す)。
6. 差し替えまたは再読込に失敗したら手順 2 の退避 ZIP から巻き戻し、
   「リストアに失敗しました。元の状態に戻しました。詳細はログを確認してください。」を表示する。
   巻き戻しにも失敗した場合は致命的エラーとして退避 ZIP の場所を明示して案内する。

## 6. エクスポート & インポート (別端末移行)

### 6.1 エクスポート

1. パスワード入力 (2 回確認、**最低 8 文字**、複雑さ要件なし)。ヒント文言
   「覚えやすい言葉の組み合わせで 8 文字以上」を添える。
2. データ一式を **復号した平文** で ZIP 化する: items は DPAPI を外した JSON
   (`items.json`)、blobs、settings.json、manifest.json (`"kind": "export"`)。
3. その ZIP 全体を §6.3 のコンテナ形式で暗号化し、保存ダイアログで任意の場所へ
   `TNDrop-export-YYYYMMDD.tndexport` として出力する。
4. 中間の平文は `%APPDATA%\TNDrop\tmp\` に展開し、成功・失敗を問わず削除する
   (メモリ上で完結できる場合はファイルに書かない実装を優先してよい)。

### 6.2 インポート

1. ファイル選択 (`*.tndexport`) → パスワード入力。
2. HMAC 検証。失敗時は「パスワードが違うか、ファイルが壊れています。」(どちらかは区別しない)。
3. 復号した ZIP を §5 の共通復元フロー (手順 1〜6) に渡す。取り込んだ履歴は次回保存時に
   この PC の DPAPI で暗号化される (特別な処理は不要、通常の Save() に任せる)。
4. **blobs パスの書き換え** (実装調査での追補): `ClipItem.ImageFile` / `ThumbFile` は
   blobs 内の相対ファイル名なのでそのまま移行できるが、`ClipItem.Paths` (Files 種別) は
   フルパスであり、画像→ファイルカード変換で **移行元の** blobs フォルダを指すエントリを
   含みうる。インポート時、旧 dataDir (エクスポート manifest に `"dataDir"` として記録) の
   `blobs\` 配下を指す Paths エントリは移行先の blobs パスへ書き換える。blobs 外の
   通常ファイルパスは書き換えない (移行先に存在しなければ既存の欠損ファイルカードと
   同じ振る舞いになる — これは許容)。このため export の manifest には `"dataDir"` を含める。

### 6.3 暗号コンテナ形式 (.tndexport, format 1)

すべて BCL のみ (追加 NuGet なし)。encrypt-then-MAC。

```
magic "TNDX" (4B) | formatVersion (1B = 0x01) | salt (16B) | IV (16B)
| ciphertext (AES-256-CBC, PKCS7)
| HMAC-SHA256 (32B, 先頭からciphertext末尾までの全バイトが対象)
```

- 鍵導出: PBKDF2 (Rfc2898DeriveBytes, SHA-256, 600,000 回, salt 16B) で 64B を導出し、
  前半 32B を AES 鍵、後半 32B を HMAC 鍵とする。
- salt / IV は `RandomNumberGenerator` で毎回生成する。
- magic / version 不一致は「TNDrop のエクスポートファイルではありません。」で弾く。
- 形式のシリアライズ / 復号は UI から独立したクラス (`ExportContainer`) にして
  ラウンドトリップ・改ざん・パスワード誤りを単体テストする。

## 7. UI

### 7.1 ダイアログ「データのバックアップ・移行」

承認済みモックアップどおりの 2 段構成 (WPF、SettingsWindow と同じ作法・スタイル):

- 上段「バックアップ一覧」: リストボックス (`[種別] 日時` を新しい順) + 右列に
  「手動バックアップ(C)」「リストア(R)」「削除(D)」。下に現在の自動バックアップ状態の
  ヒント行 (有効 / 無効、日次 + 終了時、7 世代保持)。
- 区切り線の下段「別の PC への移行」: 「エクスポート(E)...」「インポート(I)...」。
- リストア / 削除は未選択なら無効。削除は確認ダイアログを挟む。
- パスワード入力は専用の小ダイアログ (PasswordBox、エクスポート時は 2 回入力)。

### 7.2 入口と設定画面

- トレイメニューに「データのバックアップ・移行...」を追加 (「設定...」の下)。
- 設定画面に同ダイアログを開くボタンと、`AutoBackupEnabled` トグルを追加。
- 文言はすべて resx (日 / 英) に追加する。

## 8. エラー処理・ログ

- 既存規約どおり: スタックトレースは見せず「何に失敗したか + 次の行動」を表示し、
  詳細は `logs/app-YYYYMMDD.log` へ。
- バックアップ / リストア / エクスポート / インポートの開始と結果 (成功 / 失敗 / 件数) を
  INFO ログに残す。パスワードや履歴の内容はログに出さない。

## 9. 実装構成 (新規 / 変更)

| 単位 | 置き場所 | 役割 |
|---|---|---|
| `BackupService` (新規) | Core | スナップショット ZIP の作成 / 検証 / 展開、復元フロー、tmp 管理 |
| `BackupPruning` (新規) | Core | 世代刈り込みの純関数 (ファイル名一覧 → 削除対象一覧) |
| `ExportContainer` (新規) | Core | .tndexport の暗号化 / 復号 / 検証 (§6.3) |
| `BackupDialog` (新規) | UI | §7.1 のダイアログ + パスワード小ダイアログ |
| `App.xaml.cs` (変更) | App | トレイメニュー項目、SessionEnding / 終了時フック、日次契機、復元時の全面再適用 |
| `AppSettings` (変更) | Core | `AutoBackupEnabled` (既定 true)、`LastAutoBackupDate` (string、既定 "") |
| `SettingsWindow` (変更) | UI | 自動バックアップトグル、ダイアログを開くボタン、格納遅延スライダー下限 100ms |

## 10. テスト

単体テスト (xunit、既存流儀):

- `BackupPruning`: auto 7 / safety 3 / manual 無制限、境界 (ちょうど 7 件、0 件、混在)。
- `ExportContainer`: ラウンドトリップ、パスワード誤り検知、1 バイト改ざん検知、
  magic / version 不一致、8 文字未満の拒否。
- `BackupService`: 一時ディレクトリ上で ZIP 作成 → 検証 → 展開の往復、manifest 検証、
  復元失敗時の巻き戻し (差し替え途中で例外を注入)。
- 設定往復: `AutoBackupEnabled` / `LastAutoBackupDate` の Save / Load。

実機チェックリスト (docs/manual-test-checklist.md に §31 として追加):

- シャットダウン時に auto-*.zip が更新される / トレイ終了時も同様。
- リストアで履歴・ピン・設定が置き換わり、再起動なしでシェルフに反映される。
- 別ユーザー / 別 PC の ZIP を選んだときに移行案内のメッセージが出る。
- エクスポート → (別ユーザーアカウントまたは別 PC 相当で) インポートの 2 台移行が通る。
- パスワード誤りで正しいメッセージが出て、既存データが壊れない。
- 自動バックアップ OFF で日次 / 終了時が作られないこと、手動は作れること。
