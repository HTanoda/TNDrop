# TNDrop v1 設計書

- 日付: 2026-08-20
- 製作者: HIROKI TANODA (TND)
- ステータス: ユーザー承認済み (会話にて 2026-08-20 承認)

## 1. 目的

既存の同種クリップボードシェルフツールを参考にしつつ、庁内 (オフライン・イントラ環境、ランタイム未導入、
管理者権限なしの一般職員 PC) で稼働する Windows 用クリップボード・シェルフアプリを自作する。

v1 の方針:

- **一般的なクリップボードシェルフ機能の忠実な実装を最優先**。庁内業務向けの独自機能 (定型文スニペット、
  ファイル常設棚など) は v2 以降で検討する。
- 軽量 (RAM 目標: 50MB 以下)、オフラインで完結する。

## 2. 技術方式 (確定)

| 項目 | 決定 | 理由 |
|---|---|---|
| ランタイム | .NET 10 (LTS, 〜2028-11 サポート) | .NET 8 は 2026-11 EOL。保守性・改修性を最優先 |
| UI | WPF | クリップボード監視・OLE ドラッグ&ドロップ・画面端ドッキング等の Win32 連携が素直に書ける |
| 配布形態 | self-contained 単一アプリ (x64) | 本番機はランタイム未導入・オフラインのため同梱必須 |
| インストーラー | Inno Setup 7、**ユーザー単位 (管理者権限不要)** | 一般職員 PC に管理者権限がない前提。自動起動も HKCU で完結 |
| 対象 OS | Windows 10 / 11 (x64) | 庁内標準環境 |

## 3. v1 機能一覧

### 3.1 エッジシェルフ (コア UX)

- 画面端 (左 / 右、設定で選択) にマウスを寄せるとシェルフがスライドイン表示。
  スプリング (バネ) 系イージングのアニメーション。
- マウスが離れると約 800ms (設定可) で自動格納。
- 常に最前面・枠なし・タスクバー非表示のウィンドウ。
- ホットゾーン高さ (画面の 25% / 40% / 60%)、トリガー感度 (1〜7px)、
  トリガー位置 (上 / 中央 / 下) を設定可能。
- エッジ位置ヒント (シェルフが隠れている場所を示す控えめなビーコン表示)。

### 3.2 自動キャプチャ

- コピー操作 (テキスト / URL / HTML / 画像 / ファイル複数) を検知しカード化。
- 検知は `AddClipboardFormatListener` + `WM_CLIPBOARDUPDATE` のイベント駆動
  (ポーリング方式より省電力)。
- 重複除去 (直前と同一内容は追加しない。画像はハッシュ比較)。
- 自アプリ起因のコピー (カードクリックでの再コピー等) は履歴に追加しない。
- パスワードマネージャー等の除外フラグ
  (`ExcludeClipboardContentFromMonitorProcessing`、`Clipboard Viewer Ignore`) を尊重し取得しない。
- 貼り付け後に該当カードを先頭へ移動するオプション。

### 3.3 カードとドラッグ&ドロップ

- カード種別: テキスト / リンク (URL) / 画像 (サムネイル表示) / ファイル / ファイルスタック。
- リンクカード: ドメイン・タイトルのオフライン抽出、ワンクリックで既定ブラウザ起動。
  **ファビコンの外部取得は行わない** (汎用アイコン表示)。
- ドラッグアウト: OLE `DoDragDrop` によるネイティブ実装。
  ファイルは CF_HDROP (実ファイル)、テキストは CF_UNICODETEXT、画像は CF_DIB + 一時ファイルの
  複合 DataObject で、Explorer・Office・メーラー等どこへでも落とせる。
- ドラッグイン: 他アプリからテキスト・画像・リンク・ファイルをシェルフへドロップして追加。
- クリックで再コピー (クリック・トゥ・ペースト)。コピー時はインジケーターで通知。

### 3.4 スタック (グループ)

- 複数ファイルの一括コピーは自動で 1 つのスタックカードに (上限 10 アイテム/スタック。
  11 個以上を一括コピーした場合は 10 個ずつ複数スタックに分割する)。
- クリックで展開して中身を一覧 (プレビューフライアウト)。フライアウトからの個別ドラッグ可。
- 分割: スタック内の 1 ファイルを画面端へドラッグすると独立カード化。
- マージ: カードをカードの上にドラッグして結合。

### 3.5 整理・検索

- ピン留め: ピンしたカードは専用デッキに常駐し、自動削除の対象外。
- 5 カテゴリフィルター: 全て / テキスト / リンク / 画像 / ファイル。
  フィルターごとに件数バッジと「クリア」操作 (アクティブなフィルターと検索語に連動)。
- インクリメンタル検索 (テキスト内容・ファイル名・URL が対象)。
- 複数選択 (タップでトグル) + 一括操作バー (全選択 / 選択をコピー / 選択を削除 / 選択解除)。

### 3.6 プライバシー・データ保護

- シークレットモード: 有効中はキャプチャを完全停止 (トレイとシェルフ双方から切替可)。
- 自動削除タイマー: なし / 1時間 / 6時間 / 24時間 / 7日 (ピン留めは対象外)。
- 履歴は Windows DPAPI (CurrentUser スコープ) で暗号化して保存。
- 保存は原子的 (一時ファイル書込→リネーム) + .bak バックアップ。
- 外部送信は一切なし (テレメトリ・更新チェック・ファビコン取得を含む)。

### 3.7 環境適応

- マルチモニター: シェルフを表示するモニターを設定で選択。切断/再接続時は自動復旧し、
  設定は再起動をまたいで保持。
- フルスクリーン保護: 全画面アプリ (プレゼン・動画・ゲーム) を検知したらホバー起動を自動停止。
- スリープ / 復帰・ロック解除時の誤キャプチャ防止。
- ログイン時自動起動 (HKCU\...\Run、設定で ON/OFF)。
- タスクトレイ常駐: ホバー有効/無効、シークレットモード、設定、終了。

### 3.8 設定画面

- 3 カテゴリ構成: 動作 / 位置 / 外観。固定ヘッダー + カテゴリ別スクロール位置記憶。
- 動作: 自動起動、効果音、シークレット、自動削除、貼り付け後の先頭移動、格納遅延。
- 位置: エッジ左右、モニター選択、ホットゾーン高さ、トリガー感度・位置 (変更時に位置プレビュー表示)。
- 外観: 文字サイズ (小 / 標準 / 中 / 大)、コピーインジケーター様式 (4 種)、言語 (日本語 / English)。

### 3.9 フィードバック

- コピーインジケーター: キャプチャ成功時に画面端が控えめに光る (様式 4 種から選択)。
- 効果音: 音声ファイルを同梱せず、コード生成した短い合成音 (取得音・削除音・トグル音)。
  設定でまとめて ON/OFF。

## 4. 設計上の判断 (オフライン庁内適応)

| 一般的な実装 | TNDrop v1 | 理由 |
|---|---|---|
| 自動更新エンジン (GitHub 参照) | **非搭載**。更新はインストーラー再実行で上書き | 本番機はネット不可。外部通信禁止 (CLAUDE.md §2.2) |
| 30 言語対応 | 日本語 (第一言語) + 英語のみ | 庁内利用。翻訳保守コスト削減 |
| ファビコン取得 | 汎用アイコン + ドメイン表示 | 外部通信禁止 |
| Ko-fi / GitHub スター誘導 | 非搭載 | 業務アプリに不要 |
| Microsoft Store 配布 | Inno Setup のみ | 庁内配布 |
| Electron (RAM 130〜160MB) | WPF ネイティブ (目標 50MB 以下) | 非力な庁内 PC への配慮 |
| PowerShell 経由の HDROP 解析 | Win32 API 直接呼び出し | 速度・確実性。庁内 PC は PowerShell 実行制限がある場合もある |

## 5. アーキテクチャ

単一プロセス・トレイ常駐の WPF アプリ。プロジェクトは `src/TNDrop.App` 1 本 + テスト。

```
D:\TNDrop\
├── src\
│   ├── TNDrop.App\
│   │   ├── Core\          # モデル (ClipItem, Stack)、ItemStore (永続化)、設定
│   │   ├── Platform\      # Win32 相互運用 (P/Invoke)
│   │   │   ├── ClipboardMonitor.cs    # AddClipboardFormatListener
│   │   │   ├── DragDropSource.cs      # OLE DoDragDrop / DataObject 構築
│   │   │   ├── FullscreenDetector.cs  # SHQueryUserNotificationState 等
│   │   │   └── AutoStart.cs           # HKCU Run
│   │   ├── Services\      # 自動削除、効果音合成、ログ
│   │   └── UI\            # ShelfWindow, SettingsWindow, カード各コントロール
│   └── TNDrop.Tests\      # ユニットテスト (xUnit)
├── assets\                # アイコン
├── installer\setup.iss    # Inno Setup 7 (ユーザー単位インストール)
├── docs\
└── dist\                  # ビルド成果物 (.gitignore)
```

### 設計上の要点

- **エッジ検知**: グローバルマウスフックを使わず、画面端 1px の透明トリガーウィンドウの
  MouseEnter で起動する。セキュリティソフト・庁内の挙動監視に抵触しにくい。
  補助として低頻度カーソル位置ポーリング (トリガー幅の調整用) を併用してよいが、
  バッテリー/負荷に配慮しアイドル時は間隔を伸ばす。
- **データ保存**: `%APPDATA%\TNDrop\` に `items.json` (DPAPI 暗号化)、`blobs\` (画像実体 +
  サムネイル)、`settings.json` (平文でよい)、`logs\app-YYYYMMDD.log` (日次ローテーション、
  規約フォーマット、個人情報・クリップボード内容は書かない)。
- **大きいテキスト** (目安 300 文字超) は本体をディスク側に置き、メモリにはプレビューのみ保持。
- **多言語**: .resx (ja 既定 / en)。文字列は全てリソース経由。

## 6. エラー処理

- クリップボードが他プロセスに掴まれている場合はリトライ (指数バックオフ、最大 5 回) し、
  失敗したらそのコピーはスキップしてログに記録。アプリは落とさない。
- ストア破損時は .bak から自動復旧。両方壊れていたら空の状態で起動し、
  「履歴の読み込みに失敗しました。詳細はログ (logs\app-YYYYMMDD.log) を確認してください」と表示。
- 未処理例外はグローバルハンドラで捕捉しログへ。利用者にスタックトレースは見せない。

## 7. テスト方針

- ユニットテスト (xUnit): ItemStore (保存/復旧/原子性/暗号化)、重複判定、URL 判定、
  自動削除ロジック、スタックのマージ/分割、設定の読み書き。
- OS 連携部 (クリップボード監視、ドラッグ&ドロップ、フルスクリーン検知、マルチモニター) は
  手動テストチェックリストを `docs/manual-test-checklist.md` に整備し、リリース前に実施。
- 検証環境: 開発機 (ネットあり) で完結。配布前に `graph-compliance-audit` で
  オフライン依存・同梱漏れを監査する。
