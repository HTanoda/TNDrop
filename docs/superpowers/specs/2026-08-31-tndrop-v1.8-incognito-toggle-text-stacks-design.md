# TNDrop v1.8 設計書 — シェルフ上シークレットトグル + テキストスタック

日付: 2026-08-31 / 対象バージョン: 1.8.0 / ステータス: ユーザー承認済み設計 (UI モックアップ承認済み)

## 1. 目的とスコープ

利用者フィードバック 2 件に応える。

1. 意図しない登録を防ぐため、シェルフ上でシークレットモードを ON/OFF できるトグルが欲しい
2. 用途や相手で定例文を使い分けるため、テキストにもスタック機能が欲しい (スタックに名前を付けたい)

含むもの:

- シェルフヘッダーへのシークレットトグルボタン + ON 中の状態表示 (アイコン色 / バッジ / パネル配色)
- テキストカード同士のドラッグマージによるテキストスタック (既存ファイルスタックと同じジェスチャ)
- テキストスタックのフライアウト (行クリックで 1 件コピー / 行ドラッグで 1 件持ち出し / 端バンドで分離)
- スタック (テキスト・ファイル共通) への任意の名前付け

含まないもの (明示的に見送り):

- リンクカードのスタック参加 (Link は「ブラウザで開く」と専用フィルタタブの意味論を持つため v1.8 では除外。ドロップはシェイク拒否)
- テキストと画像・ファイルの混在グループ (ブレスト C 案。実需要がない)
- スタック内テキストの直接編集 (分離 → v1.7 編集 → 再マージで代替可能)
- テキストスタックカード自体の端バンド抽出 (v1.2 Task B 相当。フライアウト行の分離で足りる)
- 別画面の定型文パレット (ブレスト B 案。シェルフと二重パラダイムになるため不採用)

## 2. 機能 1: シークレットトグル

### 2.1 配置と挙動

- ヘッダーボタン列に追加: タイトル | **シークレット** | ピン | ⚙ | ? | ×。状態トグル同士 (シークレット・ピン) を隣接させ、メタ操作群と分ける
- クリックで既存の `App.SetIncognitoMode(!Settings.IncognitoMode)` を呼ぶだけ。設定の書き込み・トレイ同期・Monitor.Paused は既存の単一入口がすべて行う (新しい書き込み経路を作らない)
- トレイ / 設定画面 / 設定リストア側からの変更もシェルフに反映する必要がある。`SetIncognitoMode`・OnStartup・設定リストアの 3 箇所が既に `_trayIcon?.SetIncognito(value)` を呼んでいる — その同じ行に `ShelfWindow` への通知を並べる (`SetIncognitoVisual(bool)`)。トレイと同型の「表示を合わせるだけで change イベントを再発火しない」作法に従う

### 2.2 状態表示 (承認済みモックアップ準拠)

「ON のまま忘れて登録されない」事故を防ぐため、色に依存しない 3 信号を重ねる。

| 信号 | OFF (通常) | ON (シークレット) |
|---|---|---|
| アイコン | 目 (E890 View)、既存ヘッダーボタンと同じグレー | 斜線付きの目、紫 `#BF5AF2` |
| バッジ | なし | タイトル横にピル「シークレット」(背景 `#3A2B52` / 文字 `#D5B8F5`) |
| パネル | 背景 `#F01A1A1F` / ボーダー Transparent (現状) | 背景 `#F0221A2E` / ボーダー `#6B4E9E` (既存の 2px 透明ボーダーを使うためレイアウト変化なし) |

- 紫を選ぶ理由: ブラウザのプライベートモードで定着した色 (Familiarity)。既存アクセント `#0A84FF` はピン・選択の意味を既に持つため使わない
- 目のアイコンを選ぶ理由: モードの実体が「クリップボードの監視を止める」であり「見ていない = 斜線付きの目」が機能の直喩。南京錠は「暗号化・保護」と誤読される (TNDrop は実際に DPAPI 暗号化しており衝突が具体的)。帽子・マスクは同梱システムフォントにグリフがなく 13px で潰れる
- グリフ実装: OFF は MDL2 `E890` (View) が確実に存在。ON の斜線付きは実装時に MDL2 サポート表で Hide 系グリフの有無を確認し (rules/inno-code-section-is-pascal-script.md の一般化: 書く前に存在確認)、無ければ `E890` + 斜線 Path 2 行のオーバーレイで作る。ピンの E718/E840 差し替えと同じ「グリフ + Foreground」パターン
- 切替時はパネルの Background / BorderBrush を **200ms の ColorAnimation (ease-out、バウンスなし)** で遷移 (状態変化でありジェスチャ由来の運動ではない)。カード・検索ボックスの背景は変えない (パネル地の変化で十分伝わり、リソース差し替えの侵襲を避ける)
- ツールチップ + AutomationProperties.Name: 「シークレットモード — コピーを登録しません」
- ボタンは既存 `Header.IconButtonStyle` (Focusable=False。クリックでフォーカスを奪わない)

## 3. 機能 2: テキストスタック

### 3.1 データモデル (ClipItem)

```csharp
public List<string> Texts { get; set; } = new(); // Text スタックの本文列 (2+ でスタック)
public string? Name { get; set; }                // スタック表示名 (テキスト・ファイル共通、任意)

[JsonIgnore]
public bool IsTextStack => Kind == ClipKind.Text && Texts.Count > 1;
```

- **単一解決**: 単独テキストカードは従来どおり `Text` のみ (`Texts` は空)。テキストスタックは `Texts` が正で `Text` は null。両方に本文を持たせない (rules/one-resolution-per-related-fields.md — Text と Texts[0] のドリフトを構造的に禁止)
- `IsStack` (ファイル) は改名せず現状維持。スタック共通の表示 (名前・バッジ) が要る箇所は `IsStack || IsTextStack` を読む
- `ContentHash` = Texts を NUL 文字 (U+0000) 区切りで連結した UTF8 バイト列の `Fnv1a`。NUL はクリップボード由来のテキストに現れないため、改行を含む単独テキストや連結一致との衝突を避けられる
- 永続化: 旧 items.dat は `Texts`/`Name` 欠落 → 既定値で読める (後方互換 OK)。旧バージョンの exe が新 items.dat を読むとテキストスタックは本文なしカードに見える (ダウングレード非対応、v1.6 と同方針)。バックアップ (v1.6) は items.dat 丸ごとなので自動的に含まれる

### 3.2 ItemStore API

```csharp
public bool TryMergeTexts(string targetId, string sourceId)
public ClipItem? SplitText(string stackId, string text)
public List<ClipItem> SplitAllTexts(string stackId)   // ファイル版 SplitAll と同型
public bool SetName(string id, string? name)          // null/空白 = 名前クリア (自動タイトルに戻る)
```

- `TryMergeTexts`: 両方 `Kind==ClipKind.Text` のみ成功 (Link は false → シェイク)。単独カードの `Text` は `Texts` へ畳み込み、`Text=null` にする。完全一致の重複本文は除外。**合計 10 件超は false** (ファイルの上限と同値)。Pinned は OR。`Name` は `target.Name ?? source.Name` (無名ターゲットに名前付きソースを畳んだら名前を引き継ぐ)。source は削除、ハッシュ再計算 — すべて `TryMergeFiles` の確定作法に合わせる
- `SplitText`: 値キー (マージ時の重複除外により `Texts` 内は一意 — ファイルの path キーと同型)。残 1 件になったら `Texts` を空にして `Text` に戻す (スタック解消。ファイル版の「1 件でも Files カードのまま」とここだけ異なる — 単独テキストの正規形は `Text` であるため)。分離カードは先頭挿入・Pinned 継承
- 各メソッドのロック・`Changed` 発火・`Save()` タイミングは既存変異メソッドの実物に合わせる
- v1.7 `UpdateText` はテキストスタック id に対して false (単独カード専用。UI 側でも編集アイコンを出さない)

### 3.3 カード表示と操作

- タイトル: `Name` があれば `Name`、無ければ `Texts[0]` の先頭行 (単独テキストのタイトル導出を再利用)。サブタイトルに件数「3 件のテキスト」。**ファイルスタックのタイトルも同様に `Name` があれば `Name` を優先** (無ければ従来表示のまま)
- 件数バッジ (ShelfViewModel.Contribution): `IsStack ? Paths.Count : IsTextStack ? Texts.Count : 1`。「マージ / 分離でテキスト件数の合計が不変」というファイル版 v1.3 Task A の不変量をテキストにも適用
- フィルタ: `Kind==Text` なのでテキストタブに入る (MatchesFilter 変更なし)
- 検索 (MatchesSearch): `Texts` の各要素も部分一致対象に追加 (ヒットすればスタックカードが出る)
- **カードクリック = フライアウトを開く** (ファイルスタックと同一。ユーザー確認済み: 「開いて 1 件選ぶ」が既定操作)
- カード全体のドラッグ = 全文を `"\n"` 連結したテキストとして持ち出す (ファイルスタックの「一括持ち出し」対応物。使用頻度は低い想定だが、ドラッグが無反応になるより良い)
- 作成: テキストカードをテキストカードへドラッグ (ShelfWindow の既存マージ分岐に「両方 Text なら TryMergeTexts」を追加。拒否はシェイク)。クリップボード取り込みが既存スタックに追記されることはない (取り込みは常に新カード。現状のファイルと同じ)

### 3.4 フライアウト (StackFlyout の汎用化)

- 現在ファイルパス列 (`StackFileRow`) 前提の StackFlyout を、テキスト行も出せる行モデルに広げる (行 = アイコン/サムネイル + 主文言。テキスト行はサムネイル解決なし、先頭行を 1 行表示)
- 行クリック = その 1 件をクリップボードへコピー (カードクリックと同じ確認フラッシュ)
- 行ドラッグ = その 1 件をテキストとして持ち出し (DragDropSource のテキスト経路を再利用)
- 端バンドで放す = `SplitText` (StackGestures.IsInSplitZone をそのまま使う。バンド幅も既存定数)
- 「すべて展開」= `SplitAllTexts`
- ホバー維持・閉じ判定・世代ガードなど flyout 自体の生存規則は変更しない

### 3.5 名前付け UX

- スタックカード (テキスト・ファイル共通) のアクション列に「名前を変更」アイコンを表示 (v1.7 編集アイコンと同じ `Card.ActionButton` + Tag 分岐方式。単独カードには出さない)
- 押すと単一行の名前ダイアログ (EditDialog と同じ作法: 標準クロム、CenterScreen、ダークパレット、単一インスタンス・前面化)。空で保存 = `SetName(id, null)` で名前をクリアし自動タイトルへ戻る
- 命名はあくまで任意 — マージ時に命名を求めない (とっさの束ね操作を止めない)

## 5. テスト

単体テスト (xunit、既存流儀):

- `TryMergeTexts`: Text+Text 成功 / Link 拒否 / 10 件上限 / 重複本文除外 / Pinned OR / Name 引き継ぎ (`target.Name ?? source.Name`) / Text→Texts 畳み込みで `Text==null`
- `SplitText`: 値キー分離 / 残 1 件で `Text` 正規形へ戻る / Pinned 継承 / ContentHash 再計算
- `SplitAllTexts`: 全展開 + 元スタック削除が 1 回の Changed
- `SetName`: 設定 / クリア / 対象なし false。永続化往復 (`Texts`/`Name` が items.dat を往復する)
- `UpdateText` がテキストスタックを拒否する
- ShelfViewModel: Contribution のテキスト重み / マージ・分離往復でテキストバッジ合計が不変 / MatchesSearch が Texts 内にヒット
- 旧形式 items.dat (Texts/Name なし JSON) の読み込み互換

実機チェックリスト (docs/manual-test-checklist.md に追記):

- シェルフのトグルで ON → トレイ・設定画面の表示が追従、パネルが紫化、コピーが登録されない。トレイから OFF → シェルフ表示が追従
- テキストカード同士のドラッグマージ、フライアウトから 1 件コピー / 実マウスでの行ドラッグ持ち出し / 端バンド分離
- スタック命名 → カードタイトル反映 → 再起動後も保持
