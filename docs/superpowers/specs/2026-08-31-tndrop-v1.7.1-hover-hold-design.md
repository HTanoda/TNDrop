# TNDrop v1.7.1 設計書 — 静止カーソルでのシェルフ出入りループ修正

日付: 2026-08-31 / 対象バージョン: 1.7.1 (パッチ) / ステータス: ユーザー承認済み設計

## 1. 症状と原因

**症状** (利用者報告・実機): カーソルを画面端のトリガー位置に置いたまま動かさないと、
シェルフが「スライドイン → 格納遅延後にスライドアウト → トリガー再発火でスライドイン」を
延々と繰り返す。

**原因** (コード調査で確認): 格納判定 `ShelfWindow.IsPointerInside` はマウスイベント由来の
状態 (`MouseEnter`/`MouseLeave` のフラグ、WPF の `IsMouseOver` 等) のみで構成されている。
カーソルが静止しているとマウスイベントが発生しないため、シェルフがアニメーションで
静止カーソルの真下に来ても「ポインタは外」と判定されたままになり、格納タイマーが発火する。
格納するとトリガー帯が復帰して再びスライドインし、ループが成立する。

- 同型の欠陥は StackFlyout で実測済み (「静止カーソルの下で約 0.8 秒後に自閉」、
  StackFlyout.xaml.cs の OnHoverTick コメントに記録) で、そのときの対処が
  「イベントに頼らず実カーソル座標で判定する」だった。シェルフ本体の格納経路には
  この実座標チェックが存在しない (ArmRetractIfPointerOutside / OnRetractTick /
  IsPointerInside のいずれも実カーソル座標を照会していないことを確認済み)。

## 2. 修正方針

**格納タイマーの tick (`OnRetractTick`) の抑止条件に、実カーソル座標による物理チェックを
1 項追加する。** tick 発火時にカーソルが次のいずれかの内側にあれば、格納せず再アームする
(既存の suppress-and-re-arm ループに乗る):

1. 表示中シェルフの矩形
2. トリガー帯の矩形 — 設定 (トリガー位置=上/下 + ホットゾーン大) によってはトリガー帯が
   シェルフ矩形の外にはみ出しうるため、「トリガー位置にカーソルがあり続ける限り開いたまま」を
   全設定で成立させる

カーソルがどちらの矩形からも出れば、次の tick で従来どおり格納する。

### 変えないもの (重要)

- **`ArmRetractIfPointerOutside` / `ShelfRetract.ShouldArm` は変更しない。** タイマーの
  起動条件は従来どおりで、タイマーは走り続ける (tick が抑止と再アームを繰り返す)。
  物理チェックをアーム側に入れると「可視シェルフにタイマーが無い」状態を作りうる —
  静止カーソルは MouseEnter を登録していないため退出時に MouseLeave も来ず、タイマーが
  無ければ誰も格納できずシェルフが詰む (v1.2 Task B で確立した既存の不変条件)。
- ピン、ドラッグ猶予、フライアウト等の既存の項はすべてそのまま。
- 新しいタイマーは追加しない。ポーリングは既存 tick (RetractDelayMs、下限 100ms) に相乗り。

## 3. 実装

- **判定の純関数化** (単体テスト用): `ShelfRetract` に
  `public static bool CursorHolds(double cursorX, double cursorY, ShelfPlacement.Rect shelfRect, ShelfPlacement.Rect triggerRect)`
  を追加 — 点が 2 矩形いずれかの内側 (境界含む) にあるか。
- **ShelfWindow 側の配線**: `OnRetractTick` の `IsPointerInside` 抑止分岐を
  「`IsPointerInside || IsCursorHoldingShelf()`」に拡張。`IsCursorHoldingShelf()` (private) は:
  - カーソル座標: 既存の `MonitorGeometry.CursorDip(_area)` (フライアウトの
    `IsCursorOverShelf` と同じ取得経路 — 取得規則を二重に持たない)
  - シェルフ矩形: `Place()` で保持している配置済み `_rect`
  - トリガー矩形: `ShelfPlacement.TriggerRect(...)` を現在の設定と `_area` から算出
    (EdgeTriggerWindow の配置と同じ唯一の算出関数 — 判定規則を二重に持たない)
  - Win32 呼び出しが失敗した場合は false (= 従来挙動に倒す。開いたまま詰む方向に倒さない)
- 既存 `IsCursorOverShelf` (フライアウト用、シェルフ矩形のみ) はそのまま。実装時に共通化
  できる部分 (カーソル取得 + 点 in 矩形) があれば `CursorHolds` 経由に寄せてよいが、
  フライアウトの挙動を変えないこと。

## 4. テスト

単体テスト (`ShelfRetractTests` 既存ファイルがあればそこへ、無ければ新規):

- `CursorHolds`: シェルフ矩形内 / トリガー矩形内 (シェルフ矩形外) / 両方の外 / 境界上
  (含む) / 2 矩形が重なる場合
- 既存の `ShouldArm` テストが変更なしで green のまま (アーム側を変えていない証拠)

実機チェックリスト (§33):

- [必須] カーソルをトリガー位置に置いたまま待つ → シェルフが出て、**出たまま** (出入りを
  繰り返さない)
- カーソルをシェルフ外へどける → 格納遅延後に従来どおり格納する
- 通常のホバー操作 (出す → カード操作 → 離れて格納) が従来どおり
